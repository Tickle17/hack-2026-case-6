# Финансовый питомец — мобильное приложение для RuStore

## Что это

Мобильная игра-обучалка: ребёнок заводит виртуального питомца и ухаживает за ним,
тратя виртуальную валюту, которую надо заработать и разумно распределить.
Цель продукта — сформировать базовые навыки: планирование бюджета,
приоритизация расходов, накопления.

Целевая аудитория: **дети 7–11 лет**. Всё, что мы делаем, читается и понимается
ребёнком этого возраста без взрослого рядом.

Обучение здесь **в последствии, а не в тексте**: ядро продукта — развилка,
где игрушка стоит 10 монет, а нужные расходники 9. Ребёнок приходит к выводу
сам.

## Стек

- React Native (bare, React Native CLI — **не Expo**) + TypeScript strict
- Платформа приоритета: **Android / RuStore**. iOS — не в скоупе MVP.
- Архитектура: **Feature-Sliced Design (FSD)** — см. раздел «Архитектура»
- Процесс: **tests first** — см. раздел «Tests first»
- Пакетный менеджер: **yarn**. `npm install` / `npm run` / `npm ci` запрещены
  на уровне permissions. `npx` разрешён только для разовых генераторов
  (`npx @react-native-community/cli init`, `npx pod-install`) — не для
  установки зависимостей и не для запуска скриптов проекта.
  Единственный лок-файл в репозитории — `yarn.lock`. Появление
  `package-lock.json` = ошибка, удалить.
- Состояние: Zustand (лёгкое, без бойлерплейта — важно для скорости итераций)
- Навигация: React Navigation (native-stack)
- Персистентность: MMKV (быстрая, синхронная — подходит для игрового стейта)
- Анимации питомца: Reanimated 4 + жесты (react-native-gesture-handler)
- Визуал: **пиксель-арт**, спрайты генерируются процедурно (`tools/sprites/`)
- Тесты: Jest + React Native Testing Library

> Если стек в `package.json` разошёлся с этим списком — источником правды является
> `package.json`, а этот файл надо обновить.

## Поздняя привязка

Материалов заказчика (брендбук, гайд, рамка компетенций, возможный маскот)
у нас нет и неизвестно, когда будут. Разработку это **не блокирует**: всё
внешнее входит через реестры из таблицы ниже, а сейчас
работает на заглушках.

Правило: **если значение придёт от заказчика — его нельзя писать в коде.**
Оно живёт в реестре или конфиге за контрактом:

| Что | Где живёт |
| --- | --- |
| Цвета, шрифты, отступы | `shared/theme` |
| Компетенции | `entities/competency/config/framework.ts` |
| Виды питомцев и маскот | `entities/pet/config/species.ts` |
| Пользовательские строки | словарь слайса |
| Реплики питомца | реализация `PetVoicePort` |

Хардкод такого значения вне реестра — блокирующая ошибка на ревью, даже если
сейчас это «всё равно заглушка». Заглушка отличается от финала только
содержимым файла, и подмена не должна требовать правок в коде.

Заглушки обязаны быть **явно временными**: нейтральная палитра, пустой реестр
компетенций с `version: 'placeholder'`, оригинальные питомцы с
`origin: 'original'`. Заглушка, которую можно принять за утверждённое
решение, — хуже отсутствия заглушки.

## Архитектура: Feature-Sliced Design

```
src/
  app/          # инициализация: провайдеры, навигация, точка входа
  pages/        # экраны целиком (PetHomePage, QuestListPage, ShopPage)
  widgets/      # самостоятельные композитные блоки (PetStage, WalletBar, QuestCard)
  features/     # пользовательские сценарии-действия (feed-pet, complete-quest, spend-coins)
  entities/     # бизнес-сущности (pet, wallet, quest, competency)
  shared/       # переиспользуемое, ничего не знающее о домене
    ui/         # игровой UI-kit
    theme/      # токены из брендбука — единственный источник цветов и размеров
    lib/        # утилиты
    config/     # константы окружения
```

Внутри каждого слайса — сегменты: `ui/`, `model/`, `lib/`, `api/`, `config/`,
и обязательный `index.ts` с публичным API слайса.

**Правило импортов — жёсткое, проверяется линтером:**

- Слайс импортирует **только слои ниже себя**:
  `app → pages → widgets → features → entities → shared`
- Импорт вбок, внутри одного слоя, **запрещён**. Двум фичам нужно общее —
  оно поднимается в `entities` или `shared`.
- Импорт вверх запрещён всегда. `entities/pet` не знает про `features/feed-pet`.
- Импорт только через публичный API: `import { Pet } from '@/entities/pet'`,
  никогда не `from '@/entities/pet/model/store'`.

Куда что кладём в этом проекте:

| Что | Слой |
| --- | --- |
| Формулы экономики, тип питомца, стор кошелька | `entities/` |
| «Покормить», «выполнить задание», «купить предмет» | `features/` |
| Сцена с питомцем, панель монет, карточка задания | `widgets/` |
| Экран дома питомца, экран заданий, магазин | `pages/` |
| Кнопки, модалки, прогресс-бары, тосты | `shared/ui` |

## Tests first

Тест пишется **до** реализации. Это не рекомендация, а порядок работы:

1. Написать тест, описывающий требуемое поведение.
2. **Запустить его и убедиться, что он падает** — по той причине, по которой
   должен, а не из-за опечатки в импорте. Красный тест, который не запускали,
   не считается.
3. Написать минимальную реализацию, чтобы тест стал зелёным.
4. Отрефакторить, не трогая тест.

Что это значит на практике:

- В отчёте о работе указывать, что тест был написан первым и наблюдался красным.
- Тест формулируется от поведения, а не от реализации: `не даёт потратить
  больше, чем есть на балансе`, а не `вызывает checkBalance`.
- Обязательные к покрытию границы: 0 монет, трата больше баланса,
  максимальный уровень, длинный перерыв между сессиями, повторный тап.
- Нельзя: писать тест после кода и объявлять это TDD; подгонять тест под
  получившееся поведение; `.skip` вместо разбора причины падения.
- Исключение — **только** чистая вёрстка без логики. Там сначала снимается
  скриншот-ожидание, потом верстается. Как только в компоненте появляется
  условие или обработчик — правило действует в полную силу.

## Конвенции

- Никаких хардкодных цветов и размеров в компонентах: только токены из `shared/theme`.
- **Перед созданием нового UI-компонента проверить `src/shared/ui/`** — скорее
  всего он уже есть. Приложение собирается из готовых блоков, а не верстается
  каждый экран заново.
- Игровые формулы живут в `entities/*/lib` как чистые функции без обращения
  к времени и рандому внутри. UI не считает экономику.
- Все пользовательские строки — на русском, вынесены в словарь слайса, не инлайном.
- Коммиты: `feat(pet): ...`, `fix(economy): ...`. По одной логической
  единице на коммит.

## Проверка готовности

Задача не считается выполненной, пока не отработал соответствующий скилл:

| Что изменили | Скилл |
| --- | --- |
| Экран, компонент, анимация | `verify-ui-change` |
| Задание, текст, игровая механика, экономика | `verify-financial-content` |
| Любой код | `verify-build` |

`verify-build` проверяет в том числе, что тест был написан первым и что
границы FSD не нарушены.

## Что нельзя

- Реальные платежи, привязка карт, любые настоящие финансовые данные.
  Валюта только виртуальная, вне приложения ценности не имеет.
- Тёмные паттерны: искусственный дефицит, таймеры давления, «питомец
  умрёт, если не зайдёшь», лутбоксы, механики, поощряющие импульсивные траты.
  Питомцу может быть грустно — питомец не наказывает ребёнка.
- Реклама, аналитика с персональными данными, сбор данных о ребёнке.
- Механики, где накопление вознаграждается джекпотом. Награда за накопление
  должна быть предсказуемой и объяснимой.
- Автоматический релиз в RuStore. Публикация — всегда ручной чекпоинт человека.
